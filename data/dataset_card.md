# Dataset Card — Transaction Intelligence (synthetic descriptors)

**Version:** built from `configs/data.yaml` · seed `20260626` · `noise_level=1.0` ·
`rows_per_merchant=60`. Regenerate with `make data` (deterministic). See
[docs/01-data-pipeline.md](../docs/01-data-pipeline.md).

## Summary
Synthetic, labeled bank/card **transaction descriptor strings** for single-label multi-class
categorization (category + subtype). Generated by running a curated merchant **gazetteer** through
a probabilistic **noise model**, then split leakage-safely by merchant. Real merchant names ground
the data; the noise emulates real descriptor corruption.

## Composition
- **14,400 rows**, **240 merchants**, **11 categories / 40 subtypes**.
- Splits (by **merchant group** — no merchant spans splits):

  | split | rows | merchants |
  |-------|------|-----------|
  | train | 9,600 | 160 |
  | val   | 2,400 | 40 |
  | test  | 2,400 | 40 |

- Columns: `descriptor` (text, the model's main input), `amount` (signed float; negative = debit),
  `is_debit` (bool), `category`, `subtype` (namespaced), `merchant_id` (group key — *not* a
  feature), `source` (`synthetic`), `noise_level`.

## Statistics (train)
- Descriptor length: min 2 / median 18 / mean 18.1 / max 55 chars.
- Unique descriptors: 6,130 (63.9% of rows) — variety from the noise model.
- Debit share: 87.6%. Credits are `income/*` (and some `transfers`).
- Category share ranges 7.5%–12.5% (driven by #subtypes per category) — mild, realistic imbalance;
  we report **macro-F1** to weight rare classes equally.

## Splitting methodology
Per-subtype group assignment (4/1/1 of each subtype's 6 merchants → train/val/test). Guarantees
**(a)** no merchant in two splits (no memorization leakage) and **(b)** every subtype present in
every split. Enforced by `tests/test_splits.py`.

## Intended use / out of scope
- **Use:** training/evaluating descriptor classifiers in this project; baselines, fine-tuning,
  distillation.
- **Out of scope:** production use on real financial data without re-validation; the gold set
  ([data/gold/](gold/)) is the realistic yardstick, not these synthetic splits.

## Known limitations
- **Synthetic-to-real gap** — the model may learn the generator; watch for `test`-vs-`gold`
  divergence ([ADR 0004](../docs/decisions/0004-synthetic-first-data.md)).
- **Gazetteer coverage** — 6 merchants/subtype; breadth is a knob, expand if gold reveals holes.
- **Simplified processor-prefix assignment** — prefixes are applied probabilistically by channel,
  not by true merchant size (a deliberate simplification that also adds useful robustness noise).
- **MCC** is attached in the gazetteer but not yet emitted as a column/feature (weak-label use TBD).

## Provenance / license
Merchant names are well-known public brand names used illustratively to ground synthetic data; no
real customer or transaction data is used. All rows are programmatically generated.
